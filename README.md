# AvailabilityShield

AvailabilityShield is a Layer 7 reverse-proxy protection system with an optional local Windows Layer 4 SYN guard. The Gateway can protect the included demo app or any public HTTP/HTTPS site supplied by the lecturer, applying rate limit, delay, queue and drop decisions before forwarding traffic. MongoDB stores request logs, security events and metric snapshots; a React dashboard displays the decisions.

## Live demo

- [Open the AvailabilityShield Dashboard](https://availabilityshield-dashboard.onrender.com/)
- [API health check](https://availabilityshield-api.onrender.com/__shield/health)

The free Render deployment runs the Layer 7 gateway, protected app and React dashboard. The PyDivert Layer 4 guard remains a local Windows component. Configure a MongoDB Atlas free cluster in Render with `MONGODB_URI` before using the deployment as a persistent demo.

## Run locally

Requirements: Node.js 18+, npm, and (for Layer 4) Python 3, PyDivert and
Administrator privileges on Windows.

Install all Node dependencies:

```bash
npm run install:all
```

For the complete local demonstration, open Administrator PowerShell in the
repository folder and run:

```bash
py -3 -m pip install -r layer4/requirements.txt
npm run dev:all
```

This starts four processes: Protected App (`http://localhost:3000`), Gateway
and API (`http://localhost:4000`), React/Vite dashboard
(`http://localhost:5173`), and the Windows PyDivert Layer 4 guard. Keep this
terminal open. Press `Ctrl+C` to stop the stack.

If PyDivert is not available, the cloud-independent Layer 7 demo can be run
in three ordinary terminals instead:

```bash
npm run dev:app
npm run dev:gateway
npm run dev:frontend
```

Open `http://localhost:5173` in a browser. Layer 4 is optional for the
dashboard and must be run from an Administrator Windows terminal.

## Use the dashboard

The sidebar provides the following views:

- **Dashboard** – overall status, protected target and current traffic health.
- **Alerts** – security events and warnings generated by the Gateway.
- **Traffic Monitor** – recent requests, response codes, decisions and latency.
- **Mitigation** – allow, delay, queue and drop activity.
- **Policies** – active Layer 7 thresholds and endpoint classifications.
- **Queue** – bounded heavy-request queue and wait-time telemetry.
- **Layer 4** – PyDivert health, SYN counters, blocked sources and events. In
  the Render deployment this view reports that the Windows agent is local.
- **Reports** – export the visible metrics, events and request data.
- **Simulator** – run a bounded demo scenario. On Render it requires the
  dashboard admin token and is restricted to the included Protected App; it
  cannot generate traffic against an external target.
- **Settings** – select the public site that the Gateway protects.
- **System Health** – Gateway, database and protected-target health checks.

All dashboard data is read through the Gateway API. The dashboard does not
connect directly to MongoDB or to the protected site.

## Test a different site

The included Protected App is only the default demonstration target. To test
the project with a site supplied by the lecturer:

1. Open **Settings** in the dashboard.
2. In **Target URL**, enter the site's public `http://` or `https://` address
   (for example, `https://example.com`). Do not include a private address,
   `localhost`, or a local network IP in production.
3. Enter the configured dashboard admin token in **Admin token**.
4. Click **Check target**. A successful check displays the site's HTTP status.
5. Click **Save target**. The active target is stored in MongoDB.
6. Send traffic to the Gateway URL, not directly to the target. For the live
   demo use `https://availabilityshield-api.onrender.com/`; locally use
   `http://localhost:4000/`. The Gateway forwards the same path to the selected
   site after applying Layer 7 decisions.
7. Return to **Traffic Monitor**, **Mitigation**, **Alerts** and **Reports** to
   see the request, decision, status and timing. Response headers include
   `x-availabilityshield-decision` and `x-availabilityshield-severity`.

The target site does not need AvailabilityShield code. It must be publicly
reachable by the Render server and accept normal server-to-server HTTP(S)
requests. Private networks, localhost targets and targets requiring a browser
login are intentionally outside the supported demo flow.

Example smoke checks:

```powershell
Invoke-RestMethod https://availabilityshield-api.onrender.com/__shield/health
Invoke-RestMethod https://availabilityshield-api.onrender.com/__shield/target
Invoke-WebRequest https://availabilityshield-api.onrender.com/
```

## Validation

With the protected app and gateway running: `npm run build`, `npm run lint`, `npm test`, and `npm run validate:all`.

`validate:all` runs frontend structure/unit checks, ESLint, production build, Layer 4 policy checks, and the live backend scenarios. The live backend portion requires the app and gateway; Layer 4 packet enforcement additionally requires PyDivert and Administrator privileges.

The simulator uses an allow-listed scenario set, caps request count and
concurrency, and never executes a client-provided shell command. In local
development it targets the local Gateway. The Render **Simulator** tab is
enabled only for the included Protected App, requires `SHIELD_ADMIN_TOKEN`,
and is capped at 24 requests with four workers. It is rejected whenever an
external target is active and must not be used to load-test a third-party site.

## Render free Layer 7 deployment

Render can host the React dashboard, Gateway and Protected App for a free demo.
Apply `render.yaml` and follow [docs/deployment-render.md](docs/deployment-render.md).
